# 资料核对与补充清单

协议函页面右侧资料检查区分为三组：

- 信息未录入：当前输入没填，不代表原文件或平台里没有。按提示先核对原资料并补录，确实没有再联系业务方。
- 附件待关联：目前未关联可用文件。先查已交付 ZIP 和工程文件库，明确文件、区段及版本后关联；不能直接写成“甲方未提供”。
- 待核对：模板确认、目录或版本冲突等流程问题，不统一列成需外部补交的资料。

点击“下载资料清单”导出当前任务全部函件的 Markdown 表格，列出协议编号、单位、具体项目、当前状态和处理方式。下载不调用模型、不修改输入；任务与当前输入不一致时，清单明确注明依据上一次同步结果。

历史样例可用离线核对工具辅助整理。该工具读取已经提取的文字与资料清单，不是页面上传原文件后的通用 OCR 服务；当前也不自动解析 DWG 或从 GIS 推断主管单位。

```sh
node scripts/audit-letter-sources.mjs --cases 样例输入与来源.json --inventory 全部样例资料清单.json --out 核对结果目录 --ids S15,S35,S36,S37,S38,S39,S40
```

cases 使用回放案例格式（id、source、sourceText、input，单份函件）；inventory 是包含 path、sha256 的文件数组。工具在副本中补录明确的河道跨越塔号、坐标基准和日期前的发函单位落款，保留原文依据。已有值冲突时不覆盖，收函单位不凭文件夹或设施名称推断。旧回放产生的明确占位说明单独更正并留痕。

附件仅在限定的资料范围内按规范化名称精确对应；同名不同内容列为待核对，不跨工程自动合并。找不到精确对应时仅表示尚未定位，不能据此认定甲方未交付。路径盖章图、路径地形图等可识别为路径图；坐标表单独分类。不会伪造实际图纸或把复函作为图纸。

核对输出包括：已补录的样例输入.json、逐份资料核对结果.json。工作台原输入、历史正文和模型配置不改变。核对后的内容仍须按业务流程确认，补录不代表已定稿或已发函。
