# Excel工程与协议清单导入

**当前规则：每次Excel导入默认不勾选任何单位。请在解析确认窗口或导入后的左侧清单明确勾选。旧样例中“默认勾选”的说明已调整，工作簿指定编号仅标为推荐测试项，不再自动选中。**

进入“协议征询函”→“导入 Excel”。也可从“项目总览”→“导入工程数据”→“Excel 工程与协议清单”进入。原工程JSON入口保留在“JSON 工程数据”选项中。

1. 下载Excel填写模板，或使用提供的“征询函输入测试样例.xlsx”。
2. 上传.xlsx，或从Excel复制包含表头的清单并粘贴。点击“解析表格”。两种方式任选其一。
3. 核对工程名称、路径、版本与协议表格。确认会替换本次路径清单；有新工程编号/版本/路径时切换到该工程。关闭或取消不会写入。
4. 点击“确认导入”。清单区的“表格编辑”可直接修改单元格、新增或删除行，点击“保存清单”生效。专项技术参数仍在各行“编辑”中填写。
5. 核对工程与发函信息，确认适用模板，点击“确认清单”记录单位、区段和事项核对。需要起草时才点击“生成正文”。

## 工作表与字段

| 工作表 | 内容 |
| -- | -- |
| 工程信息 | 第一行为“字段、填写内容、说明”。工程编号、工程名称、工程版本、路径编号必填；其他字段包括电压等级、设计阶段、工程概况、路径描述、发函单位、发函日期、发文字号、联系人、联系电话、复函地址、是否测试样例。 |
| 协议清单 | 第一行为表头，每行一份函件。包含协议编号、行政区域 / 区段、部门 / 收函单位、函件类型、征询事项、征询轮次、完成情况、前次函件与意见、路径调整原因。 |
| 附件清单 | 协议编号、附件类型、文件名、测试附件内容。通过协议编号关联；真实工程只登记附件清单，实际文件在网页“附件”中上传。 |

只导入单位清单时可不含“工程信息”，沿用当前工程。“行政区域、部门”两列旧清单也可解析；缺少事项时保留为空并提示补充，不根据部门名称自行编造内容。

函件类型使用网页中的完整名称或general、grounding、water、highway、mineral、aviation、railway、seismic、military。征询轮次为首次、再次征询或路径调整后重新征询。支持最多500项，默认勾选前30项未完成协议；每次最多起草30份。表格不支持公式；请先粘贴为值。

测试样例包含3项一般路径征询。工程概况、单位名称取自历史资料；编号、征询事项、发函信息及TXT为模拟测试填写，不能用于正式发函。“是否测试样例=是”且TXT内容注明“仅测试”时，预览会提供可选的测试附件导入勾选项。默认不勾选，真实工程不使用该功能。

仅导入征询函信息不会虚构路径长度、费用等GIS指标。其他智能体需另外接入其所需数据。导入、资料修改、取消操作不调用大模型；共享模型配置保持不变。导入前的输入会在浏览器中备份，历史任务仍保留。

运行`npm test`验证规则及页面模块，运行`npm run test:letters-import`验证Excel解析接口、工程上下文、附件、三份固定模板草稿与Word/ZIP/Excel导出。联调不调用真实模型。

## 四个工程输入样例

导入窗口可下载“四工程测试样例”。工作簿按`P01_工程信息 / P01_协议清单`等名称组织四个工程；上传后先选择工程，再预览该工程清单。附件清单用“工程编号”列填写P01至P04分组，禁止混用。

P01始兴至园山67条、P02陆丰核电厂至茅湖35条、P03甲子海风开断接入19条、P04大埔电厂至嘉应42条，共163条，保留原始行政区域与部门。每个工程只有1条填写完整的测试事项，工程信息中的“本次起草协议编号”指定默认勾选项；其余记录不编造征询内容。可补齐后另行勾选起草。

四个工程也分别提供单独工作簿，文件名为P01至P04征询函输入测试样例.xlsx，不需要在四工程中选择。发函信息、前函记录与测试TXT为模拟；模板确认及清单确认仍由使用者操作。
