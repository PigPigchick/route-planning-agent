# PostgreSQL 与 RAG 使用说明

当前系统已在 Mac 安装 PostgreSQL 18.6 和 pgvector 0.8.6。数据库名为 `transmission_studio`，地址为 `127.0.0.1:5432`，仅供本机访问。连接信息保存在本机 `.env.local`，不进入 Git 或发布包。

## 已完成的接入

| 内容 | 保存方式 |
| --- | --- |
| 工程目录、工程信息、路径工作副本、协议清单及勾选 | PostgreSQL |
| 工程运行快照、任务、正文、人工复核及发出/回复记录 | PostgreSQL |
| 模板、模板历史版本、单位目录及区划资料 | PostgreSQL |
| 知识资料索引、文字片段及向量 | PostgreSQL＋pgvector |
| 上传附件、知识资料原文件及导出文件 | 项目 `.local-data` 文件目录，数据库记录其关联 |
| 模型密钥、数据库凭证 | 本机配置文件，前端不接收密钥 |

原 `records.json` 首次迁移前已备份为 `.local-data/records.pre-postgres-时间戳.json`，原文件保留。迁移标记确保重启不会重复导入旧记录。

浏览器首次连接数据库时会备份旧工程工作资料并迁入数据库；同一工程已经存在于数据库时优先使用数据库版本。修改通过修订号保护，其他窗口已更新时提示冲突，本机未同步输入仍保留。连接同一后端的浏览器可以通过“工程管理 → 切换工程”加载工程；当前后端仅监听本机，未开放其他设备远程访问。

## 日常启动

前后端保持分别启动，无需 `.command` 文件：

```sh
npm run dev:backend
```

```sh
npm run dev:frontend
```

后端启动时会自动启动本项目已经初始化的本机 PostgreSQL 数据库。无需另行在 Postgres.app 新建默认实例。

新 Mac 先安装 Node.js 22+、Python 3.10+ 和官方 [Postgres.app](https://postgresapp.com/downloads.html)，在项目目录执行：

```sh
npm install
python3 -m pip install -r requirements.txt
npm run setup:database
```

`setup:database` 创建本机数据库并启用 pgvector，自动生成随机密码并写入 `.env.local`。不会显示密码，也不会修改模型配置。使用其他 PostgreSQL 安装位置时设置 `TX_PG_BIN`；使用已有平台数据库时自行配置 `TX_DATABASE_URL`。

## 使用知识资料库

进入左侧“知识与规则”，可看到数据库状态、有效资料数量和向量模型。

1. **同步有效模板**：将当前启用的函件模板正文结构、必填要点和附件要求向量化。相同内容复用记录；模板修改或停用后，旧模板索引不再用于新函件。更新后再次同步即可。
2. **添加资料**：选择 PDF、DOCX、TXT、Markdown，或直接粘贴文字。Mac 还支持旧 DOC。填写资料名称、类别、适用函件类型及适用工程，点击“解析并入库”。扫描 PDF 需要先做 OCR；单文件最大 10MB、200 页及8万字。
3. **检索测试**：输入相关问题并选择协议类型，查看命中的原文片段与相关度。当前工程专用资料仅在相同工程编号和版本内参与检索。
4. **检索设置**：控制是否在起草时检索，设置向量模型、维度及返回片段数。当前使用共享千问服务的 `text-embedding-v4`，维度1024。模型或维度变化后应重新同步模板或入库资料。
5. **启用/停用资料**：停用后不再被检索，已有函件中的引用记录保留。

资料入库和检索会调用右上角配置的向量服务。共享模型密钥仅在后端使用，知识库接口不返回密钥。

## 起草函件

1. 新建或切换工程，填写工程资料及协议清单，勾选本次单位。
2. 确认清单后点击“生成正文 / 重新起草正文”。启用知识检索时，系统先按协议类型、模板版本和工程范围检索，再调用正文模型。
3. 生成完成后，展开“本次参考资料”查看实际使用的片段、资料名称及相关度。
4. 资料检查及正文检查通过后，由业务人员进行人工复核，再按现有流程导出。ZIP 中同时记录检索参考信息。

检索资料用于组织行文，收函单位、参数、日期和工程事实仍由本次结构化输入装配。历史资料中的工程名称、技术参数、批复和印章不会作为本工程的确认事实使用。普通资料编辑与勾选不调用正文模型。

## 备份与验证

执行 `npm run backup:database` 生成一致性的数据库备份，输出在 `outputs/数据库备份/`。数据库备份不包含附件原文件；迁移时同时保留 `.local-data/assets/`、`.local-data/knowledge/` 和需要保留的导出文件。模型配置及凭证单独保管。

执行 `npm test` 检查业务规则，执行 `npm run test:postgres-rag` 使用独立临时数据库及模拟模型验证迁移、工程保存、检索、起草及重启恢复，不修改真实工程。真实千问调用验证及截图在 `outputs/PostgreSQL_RAG接入_2026-10-30/`。

当前RAG起草接入协议征询函智能体；其他三个智能体保持现有页面和服务行为。
