## 数据库保存了什么

| 内容 | 保存位置及方式 |
| --- | --- |
| 工程目录、工程信息、协议清单、工作副本 | PostgreSQL 的 `tx_projects`，带修订号，避免旧窗口覆盖新修改 |
| 任务使用的工程快照 | `tx_contexts`，保留运行时输入 |
| 函件正文、生成状态、复核及发出回复记录 | `tx_tasks` 的结构化数据 |
| 九类可维护模板、单位资料、RAG 设置 | `tx_resources` |
| 历史函件名称、类别、来源、适用类型 | `tx_documents` |
| 历史函件原文和待索引文字 | `tx_document_text` |
| 本次归档的 Word、PDF、图片原件 | `tx_document_files`，保存原始二进制，可下载还原 |
| 可检索片段及其向量 | `tx_chunks` |
| 工程实际附件、导出文件 | 元数据进入数据库，文件仍在本机 `.local-data/assets`、`.local-data/exports` |

浏览器保留界面工作副本和待同步内容。清理浏览器缓存不会清除 PostgreSQL 中已经保存的工程和历史任务。当前数据库仅监听本机 `127.0.0.1:5432`，数据目录是项目中的 `.local-data/postgres`。连接凭据和模型密钥不写入前端或运行记录。

原先的 JSON 记录已先备份再迁入数据库。数据库启用后连接失败会明确报错，不会悄悄改用另一份 JSON 数据。

## 起草时 RAG 怎么工作

1. 设计人员填写当前工程、路径和协议事项，确认本次收函单位及事项。
2. 系统按函件类型、工程范围和有效版本筛选资料。已停用资料及其他工程专用资料不会参与本次检索。
3. 千问向量模型把本次征询主题变成向量。pgvector 用余弦相似度找出相关片段，默认最多 4 个，并过滤低相关结果。
4. 系统将这些片段作为“参考写法”，连同本工程的结构化资料传给正文模型。历史资料是参考数据，不是可执行指令。
5. 千问组织正文；单位、工程概况、路径及技术参数继续取自本次输入。历史批复、单位、联系人和参数不能直接成为新工程事实。
6. 程序检查必填项、事实与正文。通过后标记“草稿待复核”。资料不齐或检查失败会显示原因，不能把完成起草当成人工确认。
7. 预览中的“本次参考资料”保存命中的资料、片段、相关度及当时内容。修改或停用资料不会抹掉旧任务的引用记录。
8. Word 和 Excel 由程序生成。批量 ZIP 中另附 `检索参考记录.json`，便于追溯。

这属于检索增强生成，不是微调模型。新增参考资料通过建索引参与检索；普通工程编辑、补日期、换附件不会自动重新起草。

## 在哪里查看和使用

打开 [知识与规则](http://127.0.0.1:5173/#rules)，进入“知识资料库”：

- “筛选资料名称”和类别筛选只查询本机列表，不调用模型。
- “查看资料”可看提取全文、来源及 OCR 状态，并下载数据库里的原文件。
- 发函参考的“建立索引”会先展示待发送文字和模型服务地址，确认后才调用向量服务。成功后可被起草流程检索。
- “停用”让资料退出后续检索，保留原文和已有任务记录。
- “检索测试”使用所选类型和输入问题验证命中结果。
- “同步有效模板”同步当前启用的九类模板；普通模板修改不会自动外发，旧版本会退出新任务检索。

历史发函保存为“模板参考”，不会直接把旧工程内容或原文件印章放进新函件。正式函件的版式和字段要求继续由可维护的九类模板控制。复函应与发函分开使用。

已通过 135 项自动化检查，以及真实 PostgreSQL 下的工程保存、并发冲突、归档、索引、资料停用、工程范围隔离、复函过滤、起草及服务重启恢复测试。联调中的模型桩仅用于验证接口和异常；九类向量化、检索以及虚构工程的千问起草另有真实调用记录。

历史发函向量化后再次验证：九种协议类型均检索到历史发函，45份发函共59个片段均为1024维；复函与支撑材料的向量片段数为0。虚构工程实际调用千问 `qwen3.8-max` 起草，引用1个内置模板片段和3个历史发函片段，首轮事实引用清单检查未通过，系统自动修正后通过，保存为“草稿待复核”。对应Word、Excel及含引用记录的ZIP已导出，不代表正式工程已经完成业务复核。

109 份数据库原件均与源文件 SHA-256 一致，正文未发现 Unicode 替代字符；抽查 DOC、DOCX、PDF、JPG 下载字节一致。这只能证明编码与原件保存正确，不代表 OCR 和业务事实零错误。

项目 `outputs/函件资料入库_2026-10-31/` 保存入库清单和验证记录。已生成 PostgreSQL 自定义格式备份，位于 `outputs/数据库备份/`；备份包含本次函件原件与文字。工程实际附件和导出文件仍需与 `.local-data/assets`、`.local-data/exports` 一起备份。

可执行 `npm run backup:database` 生成新的数据库备份。`.local-data`、凭据、真实工程数据与数据库备份不应随源代码提交到 Git。
