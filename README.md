# 输电工程知识库构建服务项目-设计智能体研发服务项目demo

本项目用于输电设计智能体研发与演示，包含统一工作台页面及前后端实现。前端与后端将持续更新，逐步完善各智能体功能与接口集成。

## 本机运行

需要 Node.js 22+ 和 Python 3.10+。先在项目根目录安装 Word / Excel 导出依赖。

macOS / Linux：

```sh
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
```

Windows PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

运行 `npm run check:setup` 检查环境，然后在两个终端分别执行：

```sh
npm run dev:backend
```

```sh
npm run dev:frontend
```

Word 导出使用 Python 和 python-docx。默认优先识别项目 `.venv` 虚拟环境，兼容 Windows、macOS 和 Linux；也可在 `.env.local` 中设置 `TX_PYTHON` 指向已安装 python-docx 的 Python。前端仅提供 dist 静态文件；后端不提供工作台页面。

## 填写 API Key

点击工作台右上角的“设置”图标，在下拉菜单选择“大模型配置”后填写：

- API Base URL：模型服务的 OpenAI 兼容地址，一般以 `/v1` 结尾。
- 模型名称：提供方实际开放的模型 ID，可手填。下拉建议来自用户参考资料，不表示已验证服务可用。
- API Key：使用密码框粘贴。保存后点击“测试已保存配置”。

后端实际调用 `POST {baseUrl}/chat/completions`。如果服务不支持 `response_format: {type:"json_object"}`，取消 JSON 模式。输出仍须满足 JSON 结构。接口说明参见 [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat)。

密钥只保存到本机 `.local-data/model-config.json`，文件权限为 600；配置查询仅返回“是否配置”，不回传密钥。密钥不写入前端代码、localStorage、任务记录或成果包。留空保留已有密钥，勾选“清除已有密钥”可以删除。

也可复制 `.env.example` 为 `.env.local` 后填写 `LLM_BASE_URL / LLM_MODEL / LLM_API_KEY / LLM_JSON_MODE`，重启后端生效。环境变量用于首次初始化；页面保存的共享配置优先，服务重启后仍沿用最近保存的设置。`.env*` 与 `.local-data/` 已加入忽略规则，`.env.example` 仅含空密钥示例。

## 协议征询函的使用步骤

1. 选择工程路径，在“编辑输入资料”中填写工程概况、路径描述、发函单位、日期、联系人、电话和复函地址，并核对模板适用性。
2. 左侧支持新增、编辑及删除所有协议事项。点击新增只打开草稿窗口，点击“确认新增”才保存；取消、关闭、点击外侧或按 Esc 不新增。填写收函单位、区段、事项、完成情况和征询轮次。删除会更新当前预览和成果清单，已有函件归档保留历史。已完成事项默认不选。
3. 补充专项参数。支持一般路径、河道航道、公路跨越、压矿、民航、接地极、铁路、地震和军事协调九类模板。公路和河道可在“跨越明细”逐行新增、编辑、删除；可选“征询主题”只填工程名之后的主题。再次征询须补充前次函件意见，路径调整后重新征询还须提供调整原因。
4. 点击对应“附件”上传实际路径图、坐标表等。支持 PDF、Word、Excel、CSV、TXT、图片、DWG/DXF，单文件最大 10MB。文件只存本机，打包时保留原件；当前不自动解析原始空间数据。
5. “更多操作 → 生成模板草稿”无需 API Key；首次“生成正文”和后续“重新起草正文”使用已保存配置。启用流式接收后，页面持续展示当前单位、等待时间和未校验正文；刷新页面后自动跟踪运行中的任务。服务失败显示具体原因，不回退为模板。
6. 在中间预览和编辑正文，在右侧查看缺项。日期、联系人和附件保存后直接更新函件及缺项检查，不调用模型，并保留正文与人工修改；同步失败时，在提示栏点击“重试更新”；旧任务资料不一致时使用提示栏“同步资料”。修改路径、征询事项或专项事实会标记“正文待重写”，需点击“重新起草正文”，或人工编辑正文后再复核。修改已复核函件会保留历史记录并要求重新复核。
7. 正文和资料检查通过后，状态为“草稿待复核”。逐函填写复核人员、意见并确认，下载单函 Word 或批量 ZIP（函件、实际附件、协议台账、复核记录）。未人工复核的可导出版本带草稿标记；资料未齐、正文待重写、模型未完成或检查失败时不允许导出。

输入可通过 JSON 导入、导出。完整对接说明见 `LETTERS.md` 和 `dist/API.md`。

## 一键模拟完整流程

在协议征询函页面勾选要测试的单位，点击“更多操作 → 运行模拟流程”。模型在独立副本中补齐缺失资料和附件说明；程序创建模拟文字附件，起草并检查正文，自动模拟确认，生成包含各单位 Word 和附件的 ZIP。过程中显示阶段、当前单位、等待时间和流式正文预览。

无需填写人工复核表单。完成后下载 Word / ZIP，点击“返回真实资料”恢复原输入和原任务。模拟确认、虚构参数和文字占位附件均有独立标识，不能用于正式发文。模型或检查失败会显示原因，不会当作完成。该操作会实际调用已配置的模型。

## 参考资料与实现边界

两批用户资料分别用于归纳历史发函结构、专项技术字段，以及初设说明书中的协议完成情况汇总字段。未复制历史项目的联系人、电话、日期、签章和批复结论；未将旧函中的核查距离当作通用规范。

模型只接收函件类别、结构和事实占位符，负责组织中文衔接文字。工程概况、路径描述、数值和历史事实由后端原样填入；技术参数表由程序生成。结构、必要占位符、新增阿拉伯数字和部分审批断言会校验，仍须人工核对文字和工程资料。

所有内置工程与地图均为演示数据。未实现 GIS 空间分析、CAD 解析、真实发文或回函采集，系统复核不代表行政审批或正式发送。后台默认仅监听本机；正式部署需接入组织的用户认证和业务数据服务。

## 千问深度思考与流式返回

大模型配置支持“使用流式接收”和“深度思考参数”。对用户提供的百炼 qwen3.8-max 接口，可选择流式接收并开启 enable_thinking。后端通过 SSE 接收 delta.content，并保存正文预览供前端每 750 毫秒查询。未启用流式时仍显示等待时间，正文在完整响应后显示；思考阶段只显示状态，不展示推理内容。reasoning_content 不进入日志、任务或导出成果。JSON 模式是独立选项，取消时仍通过提示词要求 JSON，并执行同样的结构校验。

接口连通测试等待上限为 180 秒，任务生成在后端持续执行；前端通过任务接口查询进度。配置也可通过 LLM_STREAM=true 和 LLM_THINKING_MODE=on/off/auto 设置。调用方式参考[阿里云深度思考文档](https://help.aliyun.com/zh/model-studio/deep-thinking/)。

## 四个智能体共享模型配置

大模型配置统一从工作台右上角“设置 → 大模型配置”进入，读取本机后端同一个配置文件。未修改时继续使用当前版本；保存了修改后，后续新任务使用新版本。密钥留空保留现有密钥，明确勾选清除才会移除。配置弹窗若已过期，保存时会提示重新打开，防止覆盖其他页面的新设置。

任务启动时固定模型地址、模型名、参数和配置版本；运行中的任务及比选调用的前置路径描述使用同一快照。历史结果保留原模型和配置版本，不会随全局设置变化被改写。任务响应中的 modelConfig 不包含密钥。

后端已有完整配置时，方案比选、合规分析、路径描述的常规执行会调用共享模型。模型组织衔接文字，工程数值、费用、评分、推荐资格和待核事项由代码固定引用。比选先生成路径描述，再形成综合建议。模型失败明确报错，结果不能冒充模板成功。协议征询函主操作为“编辑输入资料”和“生成正文 / 重新起草正文”；“模板预览”位于“更多操作”，同步入口仅在资料待同步或失败时出现在提示栏，且不调用模型。前端“浏览器演示模式”仍运行本地演示；使用模型需连接业务服务。

通过接口指定 options.mode=template 可以显式使用模板；options.mode=llm 则要求完整模型配置。未指定时，有配置使用模型，无配置使用模板。

验证共享配置：npm run test:shared（使用隔离的临时后端和本机模拟模型，不修改当前配置）。
